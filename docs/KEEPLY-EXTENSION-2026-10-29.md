# keeply.收好 浏览器扩展修复与验收

日期：2026-10-29；扩展版本：1.2.15。修改范围为浏览器扩展及其测试依赖，不需要重新部署服务器。

## 用户可见变化

- 名称、弹窗标识、右键菜单和快捷键说明统一为 `keeply.收好`。
- 登录、设置、收藏状态、标题、备注、标签、列表、删除和主要错误提示使用中文。
- 新安装默认地址为 `https://keeply.facezero.online`，默认启用网页快照。已有服务器、登录状态及明确设置的开关值保留；仅将未登录的官方默认地址迁移至收好。
- 成功页区分“已保存网址”“网页快照已保存，正在提取正文”“正文已提取”“正文提取失败”，说明 AI 标签与摘要属于独立步骤。
- 快照失败时显示原因和“重试保存”；只有用户明确选择“仅保存链接（不含正文）”才降级。

## 发现并修复的问题

1. **失败被掩盖**：原保存流程捕获抓取/上传错误后继续创建纯链接，最终仍显示成功。现在中止并显示可操作的错误。
2. **权限判断过严**：原流程要求 `<all_urls>`，已通过工具栏点击获得 activeTab 权限、或仅授予当前网站权限的情况可能被静默跳过。现在尝试按当前标签页权限抓取，浏览器拒绝访问时明确报错；设置开关反映实际保存偏好。
3. **重复网址没有更新快照**：服务端去重分支提前返回，新的 `precrawledArchiveId` 可能未附加。扩展现在对已有收藏替换/附加快照、触发正文重新提取，并重新读取记录确认附件已绑定才显示成功。
4. 增加同步保存锁，避免自动保存重复进入；登录凭据写入完成后再跳转。
5. 清理抓取计时器；资源请求设置 15 秒超时；整体抓取 60 秒、上传 90 秒超时；超过 20 MiB 的快照在上传前提示，413 和授权错误给出中文说明。
6. 抓取脚本先注册消息监听，再在请求中初始化 SingleFile，使初始化失败能够反馈给弹窗。抓取前后核对网址，避免网页跳转后把正文附到错误来源。
7. 更改服务器地址时清除旧 API 密钥，避免将原服务器凭据发送到新地址。

此前内网页面未保留浏览器快照这一现象已确认，但历史失败的具体浏览器错误没有留下，不能据此断言一定是某张图片、某项权限或某个资源超时。普通合成页面在旧版抓取脚本中也能成功，新版修复的重点是上述已证实的失败路径及可靠的保存确认。

## 使用新版

扩展目录：`/Users/simon/Desktop/dev/code/karakeep/apps/browser-extension/dist`。

备用压缩包：`/Users/simon/Desktop/dev/code/karakeep/.codex/extension-check/keeply-1.2.15-chrome.zip`。

1. 打开 Chrome 的 `chrome://extensions`，找到此前加载的 Karakeep 扩展，点击重新加载。名称应变为 **keeply.收好**，版本为 **1.2.15**。继续使用原目录，无需卸载。
2. 刷新原来的文章页面，确认已登录、展开全文并滚动到底部。懒加载内容必须先实际加载到页面中。
3. 点击工具栏的收好扩展。设置中保持“保存浏览器中的全文”开启；服务器应为 `https://keeply.facezero.online`。
4. 保持弹窗打开，等待网页快照保存结果。关闭弹窗可能中断抓取或上传，不能把尚在处理当作完成。
5. 即使网址此前已收藏，也可重新打开扩展保存；新版会更新同一条收藏的快照及提取正文。
6. 点击“打开”，检查正文末尾，再在网页端手动生成摘要。自动标签完成不代表摘要已经生成。
7. 若文件过大或资源超时，关闭“同时保存图片”后重试；该模式不保证图片离线可用。若权限不足，允许扩展访问当前网站并刷新文章后重试。

iframe 中的内容、未展开或未加载的段落、虚拟滚动中已移出 DOM 的段落不能保证被完整保存。浏览器快照保存成功意味着当时可抓取的页面 HTML 已上传，不是对所有站点全文完整性的通用保证。
